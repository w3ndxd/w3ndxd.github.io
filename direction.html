Direction: where I see myself

At HZ the first two years are broad. At the end of my second year I choose a study track: Software Engineering or Applied Data Science & AI. In year 3 my minor and my internship are then in that track. To prepare, I looked into what each direction really is, where they overlap and what that means for me. My sources are the HZ website, and what I learned in my first weeks of programming.

Software Engineering

Software engineering is about building software that works, keeps working and can be changed later. It is more than programming: a team has to find out what users need, design a solution, build it, test it and keep it running. The work follows a process like this:

  1. Requirements: find out what the user or client needs
  2. Design: choose the structure of the system
  3. Build: write the code and manage it with version control (Git)
  4. Test: check the software with tests and code reviews
  5. Release and maintain: put it online, fix bugs and add features

Typical tools are programming languages like Java, JavaScript or Python, Git, databases with SQL, testing and ways of working like Agile. What counts is readable, maintainable code and good teamwork. The math here is mostly logic, discrete math and thinking about how fast an algorithm is. I have already seen a small part of this in my own project: consistent formatting, Git commits and a peer code review.

Applied Data Science & AI

Data science is about finding useful answers in data. Data scientists analyse data, recognise patterns and build smart solutions with machine learning and artificial intelligence, for example a model that predicts when a machine will break down. The work follows a cycle that is often described as CRISP-DM:

  1. Business understanding: which question must be answered
  2. Data understanding: what data do we have, and is it good enough
  3. Data preparation: clean the data and make it usable
  4. Modelling: build and train a model
  5. Evaluation: does the model really answer the question
  6. Deployment: put the result to use

Typical tools are Python, SQL, statistics, machine learning libraries and charts to explain the results. A large part of the work is preparing data, not building models. The math here is statistics, probability, linear algebra and calculus. Data work also comes with responsibility: privacy rules like the GDPR, and bias in data that can make a model unfair.

My picture of the field

The two directions are closer than they look. Both start with programming. Software engineers build the systems that collect and use data, and data scientists need clean code to make their analyses work. A machine learning model is useless until software puts it inside an app. That is why jobs like data engineer sit between the two. More and more ICT tools also use AI, so a software engineer will meet data and AI too, and both directions need to think about ethics, for example privacy.

My own direction

At this moment I lean toward Software Engineering as my base. I like building things, I learn best by doing, and my structured way of thinking fits designing and testing software. Everything else, including AI, has to be built and kept running as software.

At the same time I know that my love for math pulls me toward the data and AI side, and toward fields where programming meets physics and hardware, like simulation or software for devices. That is why I want to decide carefully, based on what I experience and not only on what I expect. My first year is my test:

  • Software Engineering if I enjoy Programming Basics, Object Oriented Programming, Software Engineering Basics and Web Application Development the most.
  • Data Science if I enjoy Foundations of Data and Data Science Basics the most, especially the statistics and modelling.
